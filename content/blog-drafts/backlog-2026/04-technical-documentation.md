# PL — PDF na stronie to za mało. Jak uporządkować dokumentację techniczną?

**Zajawka:** Instrukcja, karta produktu i deklaracja nie powinny tworzyć przypadkowej listy plików. Kupujący musi wiedzieć, do czego dokument się odnosi i czy jest właściwą wersją.

Plik nazwany „karta_final_nowa2.pdf” może być zrozumiały dla osoby, która go wczoraj zapisała. Dla klienta szukającego dokumentacji do konkretnego urządzenia nie jest wiarygodną informacją. Problemem nie musi być sam PDF. Często brakuje kontekstu, który pozwala wybrać właściwy dokument.

Na stronie przemysłowej dokumentacja jest częścią informacji o produkcie. Powinna być powiązana z modelem, wariantem, językiem i zakresem zastosowania. Zanim dołożysz wyszukiwarkę plików, warto uporządkować te zależności.

## Każdy dokument potrzebuje właściciela

Ustal, kto zatwierdza publikację i kto odpowiada za późniejsze zmiany. Dostawca strony może obsługiwać techniczne dodawanie plików, ale nie powinien zgadywać, która rewizja specyfikacji jest prawidłowa.

Przydatny rejestr zawiera nazwę dokumentu, identyfikator, wersję, datę obowiązywania, język i produkt, którego dotyczy. Nie wszystkie informacje muszą zajmować główne miejsce na stronie. Powinny jednak istnieć w uporządkowanym źródle danych, żeby aktualizacja nie zależała od pamięci jednej osoby.

## Opisuj plik przed pobraniem

Kupujący powinien zobaczyć rodzaj dokumentu, wersję językową, format i rozmiar, zanim otworzy plik. Jest to szczególnie przydatne na telefonie lub słabym połączeniu. Link „Pobierz” bez opisu zmusza do sprawdzania plików po kolei.

Najważniejsze parametry produktu warto pokazać również jako tekst na stronie. Dzięki temu użytkownik może szybko ocenić dopasowanie bez pobierania całej instrukcji. To nie oznacza zastępowania dokumentu wymaganego w danym procesie. Chodzi o czytelne wprowadzenie i wskazanie właściwego źródła szczegółów.

## Aktualizacja bez mieszania wersji

Przy wymianie pliku trzeba zdecydować, co ma się stać ze starym adresem. Dokument dotyczący wycofanego modelu może nadal być potrzebny jego użytkownikom. Usunięcie go bez ścieżki do archiwum nie zawsze jest dobrym rozwiązaniem.

Z drugiej strony adres opisany jako „aktualna instrukcja” nie powinien prowadzić raz do starego, raz do nowego pliku w zależności od cache. Spójne nazwy wersji, zasady przekierowań i sprawdzenie po wdrożeniu pomagają ograniczyć takie pomyłki. Archiwalne materiały trzeba wyraźnie oznaczyć.

## Dokument publiczny czy materiał po kontakcie?

Podstawowa karta produktu i poufny rysunek wykonawczy mogą wymagać zupełnie innych zasad udostępniania. Samo ukrycie linku w menu nie jest kontrolą dostępu. Decyzję o publikacji powinien zatwierdzić właściciel informacji.

Dobry porządek w dokumentacji nie kończy się na dniu uruchomienia strony. Potrzebuje procesu aktualizacji oraz prostego testu: czy osoba, która nie zna struktury firmowych folderów, potrafi znaleźć właściwy dokument do konkretnego produktu?

# EN — Technical documentation needs more than a PDF download link

**Excerpt:** Manuals, product sheets and declarations should not become an arbitrary file list. Buyers need to understand what a document covers and whether it is the appropriate version.

“Datasheet_final_new2.pdf” may make sense to the person who saved it yesterday. It tells a customer looking for a particular machine’s documentation very little. The problem is not necessarily the PDF format. It is often the missing context needed to select the right document.

On an industrial website, documentation forms part of the product information. It should be associated with the relevant model, variant, language and application scope. Organise those relationships before adding another file-search tool.

## Give the information an owner

Decide who approves publication and who is responsible for later revisions. A website supplier can handle the technical upload, but should not have to guess which specification revision is correct.

A useful register records the document name, reference, revision, effective date, language and associated product. Not every field needs prominent placement on the public page. The information should nevertheless exist in a structured source so that updates do not depend on one person remembering the details.

## Explain the download before opening it

Show the document type, language, format and file size before the visitor opens it. This is particularly useful on a phone or a weak connection. A row of identical “Download” links makes people inspect files one at a time.

Present key product specifications as page text as well. Buyers can then assess basic suitability without downloading an entire manual. That does not replace any document required by the relevant process. It provides a readable introduction and a clear route to the detailed source.

## Keep revisions distinguishable

When replacing a file, decide what should happen to its old address. Documentation for a discontinued model may still be needed by people operating it. Deleting it without an archive route is not always appropriate.

Conversely, a link labelled “current manual” should not return different revisions depending on cached responses. Consistent revision names, redirect rules and a check after release help reduce this risk. Archive documents should be clearly identified as such.

## Decide what can be public

A basic product sheet and a confidential manufacturing drawing may require different access arrangements. Removing a link from the navigation does not create access control. The information owner should approve the publication decision.

Documentation management continues after launch. It needs an update process and a straightforward test: can somebody unfamiliar with the company’s folder structure find the appropriate document for a particular product? If they cannot, another folder of PDFs will not solve the underlying problem.
